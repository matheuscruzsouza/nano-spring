📜 Diagnósticos de Campo, Perfis & Execução Assíncrona (v1.9.0)

A versão v1.9.0 do Nano-Spring eleva a maturidade operacional para aplicações em produção em dispositivos Android remotos (PDVs SmartPOS, totens de autoatendimento, hubs IoT e gateways industriais).

✨
Diagnósticos remotos sem necessidade de depurador ADB conectado: inspeção de logs em tempo real via HTTP, rotação automática com teto de disco, perfis de configuração segregados e métodos assíncronos não bloqueantes com CompletableFuture.

1. Rotação de Logs Local em Armazenamento Interno

Dispositivos embarcados operam 24/7 sem intervenção manual. O RotatingFileLogger garante que os logs persistam no armazenamento interno seguro do app (context.getFilesDir() + "/logs/nano-spring.log"), prevenindo que a memória flash do dispositivo seja saturada através de rotação geracional controlada.

# assets/application.properties
# Habilita ou desabilita gravação em disco
nano.logging.enabled=true

# Nível mínimo de log (TRACE, DEBUG, INFO, WARN, ERROR)
nano.logging.level=INFO

# Teto máximo de tamanho do arquivo antes de rotacionar (em MB ou KB)
nano.logging.max-size-mb=5
# nano.logging.max-size-kb=1024

# Quantidade de arquivos de histórico mantidos (.1, .2, .3)
nano.logging.max-history=3

Utilizando o NanoLogger no seu Código

O NanoLogger grava simultaneamente no Logcat nativo do Android e no buffer circular/arquivo rotativo em disco:

import com.github.matheuscruzsouza.nanospring.logging.NanoLogger;

@Service
public class ImpressaoService {

    public void imprimirCupom(Venda venda) {
        NanoLogger.info("IMPRESSAO", "Iniciando spooler para venda: " + venda.getId());
        try {
            // comunicação com hardware de impressora térmica
        } catch (Exception e) {
            NanoLogger.error("IMPRESSAO", "Falha de hardware na impressora", e);
        }
    }
}

2. Endpoint Remoto de Diagnóstico: /actuator/logfile

A equipe de suporte técnico e pós-venda pode auditar remotamente os logs de um totem ou POS diretamente via HTTP, sem precisar de acesso root ou cabo USB:

  • GET /actuator/logfile — Retorna as últimas 500 linhas em text/plain; charset=utf-8.
  • GET /actuator/logfile?lines=100 — Retorna especificamente as últimas 100 linhas.
  • GET /actuator/logfile?all=true — Retorna o log completo arquivado.
# Exemplo de consulta remota via cURL
curl -i http://pdv-caixa-01.local:8080/actuator/logfile?lines=50

# Resposta:
# HTTP/1.1 200 OK
# Content-Type: text/plain; charset=utf-8
# Cache-Control: no-cache, no-store, must-revalidate
#
# 2026-09-30 18:00:01.123 [NanoThread-1] INFO SERVER_OK - SERVIDOR RODANDO ONLINE NA PORTA 8080 (timeout=5000ms)!
# 2026-09-30 18:00:15.892 [NanoThread-2] INFO IMPRESSAO - Iniciando spooler para venda: 4891

3. Perfis de Ambiente (Profiles)

Segregue ambientes de desenvolvimento, homologação e produção facilmente com o mesmo padrão consagrado do Spring Boot: application-{profile}.properties.

# assets/application.properties
server.port=8080
nano.logging.level=INFO
nano.datasource.name=banco_prod.db

# Ativação do perfil (também configurável via System Property ou Environment Variable)
nano.profiles.active=dev

Ao definir nano.profiles.active=dev, o Nano-Spring carrega e sobrepõe automaticamente as configurações de assets/application-dev.properties:

# assets/application-dev.properties
server.port=9090
nano.logging.level=DEBUG
nano.datasource.name=banco_dev.db

Múltiplos perfis podem ser combinados separando por vírgula (ex: dev,pos).

4. Métodos Assíncronos Não Bloqueantes (CompletableFuture<T>)

Em sistemas comerciais embarcados, determinadas operações são inerentemente lentas: comunicação Bluetooth com pinpads, impressão térmica de cupons fiscais, e consultas a gateways TEF.

Ao retornar CompletableFuture<T>, o endpoint executa fora da thread do dispatcher do servidor. Caso o tempo de execução ultrapasse o teto definido, o framework responde automaticamente com 408 Request Timeout.

@RestController("/api/pos")
public class PosController {

    @Autowired
    private PinpadService pinpadService;

    @PostMethod("/transacao")
    public CompletableFuture<ResponseEntity<Map<String, Object>>> processarPagamento(
            @Valid @RequestBody TransacaoRequest req) {

        return CompletableFuture.supplyAsync(() -> {
            // Comunicação demorada com o leitor EMV / chip
            ComprovanteTEF comprovante = pinpadService.capturarCartao(req.getValorCentavos());
            
            Map<String, Object> resposta = new HashMap<>();
            resposta.put("nsu", comprovante.getNsu());
            resposta.put("autorizado", true);

            return ResponseEntity.status(HttpStatus.CREATED).body(resposta);
        });
    }
}

Configuração do timeout assíncrono no application.properties:

# Timeout em segundos para CompletableFuture antes de devolver HTTP 408
nano.async.timeout-seconds=25

5. Timeout de Leitura do Socket (nano.server.read-timeout)

Ambientes de chão de fábrica ou redes Wi-Fi instáveis exigem controle fino de sockets ociosos (Slowloris attacks ou desconexões súbitas de clientes):

# Tempo limite em milissegundos para leitura de dados no socket NanoHTTPD (padrão 5000 ms)
nano.server.read-timeout=10000
