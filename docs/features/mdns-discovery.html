🔍 Descoberta mDNS & Acesso Direto (.local)

O Nano-Spring implementa uma solução integrada de anúncio Zeroconf / Bonjour com resolução direta de Host (registro A). Isso permite acessar seu servidor no Android através de um endereço amigável direto no navegador:

🌐
Digite no Chrome, Safari, Edge ou Firefox de qualquer computador na mesma rede Wi-Fi:
http://meu-servidor-android.local:8080/

🔬 Por que o NsdManager puro do Android não resolve o navegador?

O NsdManager nativo do Android anuncia apenas o ponteiro de serviço DNS-SD (_http._tcp.). Quando um navegador web tenta resolver http://servidor.local, ele envia uma query DNS padrão solicitando o endereço IP (registro A) na porta UDP 5353.

O Nano-Spring inclui o MdnsHostResponder, um socket multicast em Java puro que escuta em 224.0.0.251:5353 e responde às consultas do navegador com o endereço IPv4 ativo do celular.

⚙️ Configuração via application.properties

assets/application.properties 
# Habilita o anúncio de rede mDNS
nano.nsd.enabled=true

# Nome do host anunciado na rede (acessível como http://meu-servidor.local:porta)
nano.nsd.name=meu-servidor

# Tipo do serviço DNS-SD (padrão: _http._tcp.)
nano.nsd.type=_http._tcp.

# Habilita o responder para navegadores (padrão: true)
nano.nsd.host-resolution=true

💻 Ativação Programática no Código

Você pode ligar ou desligar o mDNS em tempo de execução através da instância do Server:

ServerSetup.java 
// Inicia o responder com o nome 'totem-loja' e resolução direta habilitada:
server.enableNsd("totem-loja", true);

// Desativa o responder e libera portas e multicast locks:
server.disableNsd();

🛡️ Permissão Multicast Obrigatória

No AndroidManifest.xml, além da permissão de Internet, adicione:

AndroidManifest.xml 
<uses-permission android:name="android.permission.CHANGE_WIFI_MULTICAST_STATE" />
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
