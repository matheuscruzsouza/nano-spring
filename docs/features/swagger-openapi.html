Documentação / Core Web / Swagger & OpenAPI 3.0

📑 Swagger & OpenAPI 3.0 Embutido

O Nano-Spring inclui um gerador dinâmico de documentação interativa compatível com OpenAPI 3.0.1 e uma interface gráfica Swagger UI ultra-leve embutida (~15 KB, sem dependências npm ou CDN externas).

💡 100% Funcional Offline: Ao contrário dos Swagger UIs tradicionais que exigem downloads de 8 MB+ ou conexões CDN na nuvem, o Nano-Swagger roda com HTML5/CSS/JS nativo e auto-contido. É ideal para PDVs, totens e TV Boxes sem acesso à internet.

🚀 Como Acessar

Por padrão, o Swagger já vem habilitado em seu servidor Nano-Spring:

  • Interface Interativa: http://<ip-do-dispositivo>:8080/swagger-ui (ou /swagger-ui.html)
  • Especificação JSON OpenAPI 3.0: http://<ip-do-dispositivo>:8080/v3/api-docs

⚙️ Configuração via application.properties

Personalize o título, a versão e a descrição que aparecem na documentação:

src/main/assets/application.properties 
# Habilitar ou desabilitar documentação (default: true)
nano.swagger.enabled=true

# Metadados OpenAPI 3.0
nano.swagger.title=PDV Smart API
nano.swagger.version=1.0.0
nano.swagger.description=API REST de Vendas e Integração Local
nano.swagger.server-url=/

🏷️ Anotações Disponíveis

Utilize as anotações do pacote com.github.matheuscruzsouza.nanospring.openapi.annotation para enriquecer seus endpoints:

Anotação Alvo Descrição
@Tag(name, description) Classe ou Método Agrupa endpoints em categorias lógicas na interface
@Operation(summary, description, deprecated) Método Descreve o propósito da rota e sinaliza depreciação
@Parameter(description, example, required) Parâmetro ou Campo Adiciona descrição detalhada e exemplo para preenchimento
@ApiResponse(responseCode, description, responseClass) Método (Repetível) Documenta múltiplos códigos HTTP de retorno e schemas

💻 Exemplo Prático de Controller Documentado

UserController.java 
package com.exemplo.pdv.controller;

import com.github.matheuscruzsouza.nanospring.annotation.*;
import com.github.matheuscruzsouza.nanospring.http.HttpStatus;
import com.github.matheuscruzsouza.nanospring.http.ResponseEntity;
import com.github.matheuscruzsouza.nanospring.openapi.annotation.*;
import com.github.matheuscruzsouza.nanospring.validation.*;

@Tag(name = "Usuários", description = "Operações de gestão de usuários do caixa")
@RestController("/api/users")
public class UserController {

    @Operation(summary = "Buscar usuário por ID", description = "Retorna detalhes cadastrais")
    @GetMethod("/:id")
    public ResponseEntity<UserDTO> findById(
            @PathVariable("id") @Parameter(description = "ID do usuário", example = "1") Long id
    ) {
        UserDTO user = new UserDTO("João Silva", "joao@email.com", 28);
        return ResponseEntity.ok(user);
    }

    @Operation(summary = "Criar novo usuário", description = "Cadastra usuário validando campos")
    @ResponseStatus(HttpStatus.CREATED)
    @ApiResponse(responseCode = 201, description = "Criado com sucesso", responseClass = UserDTO.class)
    @ApiResponse(responseCode = 400, description = "Dados inválidos")
    @PostMethod("")
    public ResponseEntity<UserDTO> create(@Valid @RequestBody UserDTO dto) {
        return ResponseEntity.status(HttpStatus.CREATED).body(dto);
    }
}

🛡️ Mapeamento Automático de Schemas e Validação (Bean Validation)

O gerador inspeciona automaticamente seus DTOs e reflete regras de validação (como tamanho mínimo, formato de email e restrições numéricas) diretamente no JSON Schema do OpenAPI:

UserDTO.java 
package com.exemplo.pdv.dto;

import com.github.matheuscruzsouza.nanospring.openapi.annotation.Parameter;
import com.github.matheuscruzsouza.nanospring.validation.*;

public class UserDTO {
    @NotBlank
    @Size(min = 3, max = 60)
    @Parameter(description = "Nome completo do operador", example = "Maria Santos")
    private String name;

    @NotNull
    @Email
    @Parameter(description = "E-mail de acesso", example = "maria@empresa.com.br")
    private String email;

    @Min(18)
    @Max(100)
    private int age;

    public UserDTO() {}
    public UserDTO(String name, String email, int age) {
        this.name = name;
        this.email = email;
        this.age = age;
    }
    // Getters e Setters...
}

🎯 Interface Interativa ("Try it out")

Na interface web embutida, desenvolvedores e equipes de integração podem:

  1. Filtrar rotas em tempo real pelo campo de busca superior.
  2. Expandir qualquer endpoint para visualizar parâmetros, headers e corpo de requisição.
  3. Preencher valores de teste diretamente nos formulários.
  4. Clicar em "Executar (Try it out)" para disparar requisições fetch() reais contra o servidor.
  5. Inspecionar a latência (tempo de resposta em ms), o código HTTP e o JSON retornado com formatação legível.
