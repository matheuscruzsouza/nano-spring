🚀 Versão 2.5.0 - Otimização Nativa de Streaming (HTTP 206 Partial Content)

Notas de Versão 2.5.0

A versão 2.5.0 traz uma reformulação arquitetural no pipeline de streaming de mídia no módulo nano-spring-web. Com cache LRU agnóstico de cabeçalhos em RAM (StreamHeaderCache), suporte híbrido memória + disco (FastFileResourceRegion) e buffer de leitura sequencial de 512 KB, o framework elimina latência de inicialização de players HTML5 e reduz drasticamente syscalls na memória flash do Android.

⚡ Cache LRU de Cabeçalhos em RAM: StreamHeaderCache

Aplicações e players modernos de áudio e vídeo emitem múltiplas requisições Range iniciais consecutivas para extrair metadados e tabelas de índice (ID3v2, moov atom, FLAC headers). O StreamHeaderCache atua em memória RAM:

  • Fast-Start Imediato: Entrega os primeiros bytes de contêineres de mídia em 0ms de I/O em disco para arquivos frequentes ou recém-acessados.
  • Agnóstico e Seguro: Implementado sem dependências proprietárias do Android, permitindo execução tanto na JVM padrão de testes quanto no runtime Android com controle estrito de memória heap para evitar OutOfMemoryError.

🚀 FastFileResourceRegion: Pipeline Híbrido RAM + Disco

O FastFileResourceRegion substitui a antiga leitura não-bufferizada ou com buffers reduzidos:

  • Buffer Sequencial de 512 KB: Reduz a frequência de syscalls de leitura na memória flash do dispositivo móvel.
  • SequenceInputStream Bridge: Quando um offset inicial coincide com a fatia em cache, combina seamlessly o buffer de memória com o canal de disco (FileChannel) sem alocações intermediárias de heap.
  • Retrocompatibilidade Transparente: FileResourceRegion estende FastFileResourceRegion, beneficiando código legado sem necessidade de refatoração.

⚙️ Configurações em application.properties

Ajuste os parâmetros de cache e buffer de acordo com as necessidades do aplicativo:

application.properties 
# Habilita ou desabilita o cache LRU de cabeçalhos (padrão: true)
nano.storage.stream.header-cache.enabled=true

# Tamanho do bloco inicial mantido em cache por arquivo (ex: 512 KB)
nano.storage.stream.header-cache.chunk-size=524288

# Limite máximo de memória reservado para o cache de streaming (ex: 8 MB)
nano.storage.stream.header-cache.max-memory=8388608

# Tamanho do buffer de leitura sequencial do disco (padrão: 512 KB)
nano.storage.stream.disk-buffer-size=524288

🏷️ Injeção Automática de ETag e Cache-Control

O ByteRangeHandler agora injeta automaticamente os cabeçalhos Cache-Control: public, max-age=3600 e ETag: "{length}-{lastModified}" nas respostas 200 OK e 206 Partial Content, permitindo validação condicional e cache eficiente no cliente.

📜 Histórico: Novidades da v2.4.1

A versão 2.4.1 trouxe otimizações críticas de latência de socket e escalonamento do pool de threads, expiração baseada em inatividade no Rate Limiter, cache HTTP para assets estáticos e suporte ao Android SDK 36 com AGP 8.7.3 e Gradle 8.10.2.

⚡ Otimização de Socket: FastSocketWrapper (Zero Reverse DNS & TCP_NODELAY)

Em redes VPN virtuais (como ZeroTier e Tailscale) ou redes locais sem servidor DNS reverso, chamadas internas a InetAddress.getHostName() podiam bloquear conexões por vários segundos aguardando timeout de registros PTR. O novo FastSocketWrapper resolve isso na camada de transporte:

  • Zero Reverse DNS Lookup: Pré-popula o hostname do InetAddress com o próprio endereço IP em 0ms, eliminando bloqueios de DNS reverso.
  • TCP_NODELAY Ativo: Desabilita o algoritmo de Nagle nos sockets aceitos para envio imediato de pacotes HTTP e eventos SSE sem atraso de bufferização.

🧵 Escalonamento Rápido no ThreadPoolAsyncRunner

O pool de threads do servidor HTTP agora prioriza a criação de threads de trabalho até atingir maxPoolSize antes de enfileirar tarefas na LinkedBlockingQueue. Isso evita que requisições concorrentes aguardem na fila enquanto o pool ainda possui capacidade de processamento ociosa.

📦 Cache HTTP em Arquivos Estáticos e Expiração no Rate Limiter

  • Cache-Control em /static/: Respostas de assets estáticos agora incluem o cabeçalho Cache-Control: public, max-age=3600, reduzindo tráfego repetitivo e consumo de CPU/bateria.
  • Limpeza de Buckets no TokenBucketRateLimiter: A remoção de buckets ociosos agora rastreia o timestamp real da última requisição por cliente (expirando após 60s de inatividade), prevenindo vazamento de memória mesmo para clientes com tokens parcialmente consumidos.
  • Build & SDK 36: Atualização do Android Gradle Plugin para 8.7.3 e Gradle Wrapper para 8.10.2 com suporte nativo ao compileSdk 36.

🎨 Histórico: Novidades da v2.4.0

A versão 2.4.0 introduziu a anotação @Hidden para controle granular de visibilidade no OpenAPI e a capacidade de substituição completa do estilo CSS da interface do Swagger UI via arquivo externo configurado em application.properties.

🙈 Anotação @Hidden

Permite ocultar completamente rotas ou controllers inteiros da especificação gerada em /v3/api-docs e da interface interativa /swagger-ui:

Exemplo: Ocultando Controller ou Métodos do Swagger 
@RestController("/api/internal")
public class InternalController {

    @Hidden // Apenas este método não será exposto no Swagger
    @GetMethod("/metrics")
    public ResponseEntity<Map<String, Object>> metrics() {
        return ResponseEntity.ok(Map.of("status", "ok"));
    }

    @GetMethod("/public-info")
    public ResponseEntity<String> info() {
        return ResponseEntity.ok("Visible endpoint");
    }
}

@Hidden // O controller inteiro e todas as suas rotas ficam ocultos no Swagger
@RestController("/api/admin")
public class AdminController {
    // ...
}

🎨 Customização de CSS do Swagger UI

Agora é possível injetar seu próprio tema ou layout CSS substituindo o CSS padrão embutido do Swagger:

src/main/assets/application.properties 
# Substitui o CSS padrão por um arquivo customizado em assets/ ou caminho local
nano.swagger.css-path=swagger-theme.css

🔐 Histórico: Novidades da v2.3.0

A versão 2.3.0 adicionou a interface AuthenticationProvider para suporte a autenticação customizada (JWT Bearer Token, API Key) no @Authenticated:

Exemplo: Implementando validação de JWT no @Authenticated 
@Service
public class JwtAuthenticationProvider implements AuthenticationProvider {

    @Override
    public boolean authenticate(NanoHTTPD.IHTTPSession session) {
        String authHeader = session.getHeaders().get("authorization");
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            return false;
        }

        String token = authHeader.substring(7);
        return JwtValidator.validate(token);
    }
}

🎧 Histórico: Novidades da v2.2.0

A versão 2.2.0 adicionou suporte nativo a Byte Range Requests (HTTP 206 Partial Content) conforme a RFC 7233:

  • Zero Memory Buffering: Seek direto via FileChannel sem alocar buffers no heap do Android.
  • ResourceRegion & BoundedInputStream: Streaming de áudio/vídeo e arquivos locais com encerramento determinístico.

📦 Histórico: Novidades da v2.1.1

A versão 2.1.1 foi uma atualização de manutenção e correção crítica focada em formulários HTML e binding de parâmetros:

  • Parâmetros String: Constrói a query string URL-encoded correspondente (ex: campo=valor&outro=123).
  • Parâmetros Map<String, String>: Injeta uma cópia direta dos parâmetros recebidos via formulário.
  • DTOs / POJOs: Converte a árvore de propriedades para o objeto Java correspondente via Gson, com suporte integral à validação via @Valid e @NotNull.
Exemplo: Bind transparente com DTO e validação 
@PostMethod("/tickets")
public ResponseEntity<String> salvarTicket(@Valid @RequestBody TicketDto dto) {
    // Funciona perfeitamente tanto com JSON quanto com application/x-www-form-urlencoded!
    return ResponseEntity.ok("Criado: " + dto.getTitulo());
}

💡 Suporte a @RequestParam Map<String, String>

A anotação @RequestParam agora possui value() default "" (opcional). Quando declarada em um parâmetro do tipo Map sem nome específico, o Nano-Spring injeta todos os parâmetros recebidos da requisição:

Injeção dinâmica de parâmetros 
@PostMethod("/processar")
public ResponseEntity<Map<String, String>> processar(@RequestParam Map<String, String> params) {
    return ResponseEntity.ok(params);
}

🔋 Histórico: Novidades da v2.1.0

A versão 2.1.0 introduziu:

  • Battery Management & Notifications: Módulo nativo com BatteryService, BatteryHelper e BatteryNotificationHelper para monitorar nível de bateria, temperatura e emitir alertas no Android.
  • Lifecycle Hooks no NanoSpringService: Método onLowBattery() para degradação graciosa em quedas de energia.
  • Segurança Básica: Introdução da anotação @Authenticated para proteção de endpoints com Basic Auth.

🧩 Histórico: Novidades da v2.0.0

A versão 2.0.0 marcou a grande fragmentação modular do framework:

  • Modularização: Fragmentado em nano-spring-core, nano-spring-web, nano-spring-data e nano-spring-discovery.
  • Perfis Low Memory Dinâmicos: Detecção automática de dispositivos com 2GB ou menos de RAM para economia agressiva de threads e memória.
